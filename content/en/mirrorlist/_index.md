Gentoo mirrors carry several resources:

- **Gentoo ebuild repository**: the ebuilds and metadata Portage uses to resolve and build packages, synchronized over Git or rsync.
- **Distfiles**: package source files downloaded by Portage, selected with `GENTOO_MIRRORS` in `make.conf`.
- **Stage 3 and the official binary package host**: available under `releases/` on HTTP mirrors that synchronize them.

These mirrors do not provide ebuilds. Pair them with an rsync or Git sync source for the Gentoo ebuild repository; see the setup instructions below.

Below is a **tested summary table** listing each mirror's distfiles URL and the sync methods it supports; the per-method config is in the collapsible tutorials further down.

{{< callout type="info" >}}
The Gentoo ebuild repository and Distfiles are configured separately. Git, rsync and HTTP services may also be provided by different mirrors.
{{< /callout >}}

{{% details title="Synchronize the Gentoo ebuild repository with Git" %}}

{{< gz-mirror name="gentoo-git" set="gentoo_git" >}}

Install `eselect-repository`:

{{< gz-cmd path="shell" sudo="true" slot="gentoo-git" set="gentoo_git" >}}
emerge --ask app-eselect/eselect-repository
eselect repository remove -f gentoo
eselect repository add gentoo git @@SRC@@
emaint sync -r gentoo
{{< /gz-cmd >}}

Remove the current Gentoo ebuild repository configuration and local copy, then add the Git repository from the selected mirror. Mirrors can have different synchronization progress; when changing Git mirrors, remove and add the repository again.

With CERNET selected, git prints `warning: redirecting to ...`, because CERNET routes the request to the nearest member mirror. The sync itself completes normally.

For manual configuration or changing mirrors, edit the file under `/etc/portage/repos.conf/` that contains the `[gentoo]` section. For a new configuration, create `/etc/portage/repos.conf/gentoo.conf`; configurations generated by `eselect-repository` are stored in `/etc/portage/repos.conf/eselect-repo.conf`.

Complete configuration example:

{{< gz-cmd path="/etc/portage/repos.conf/gentoo.conf" slot="gentoo-git" set="gentoo_git" >}}
[gentoo]
location = /var/db/repos/gentoo
sync-type = git
sync-uri = @@SRC@@
auto-sync = yes
{{< /gz-cmd >}}

When switching from rsync to Git for the first time or changing mirrors, remove the existing local repository and synchronize it again:

{{< gz-cmd path="shell" sudo="true" >}}
rm -rf /var/db/repos/gentoo
emaint sync -r gentoo
{{< /gz-cmd >}}

See [Portage with Git](https://wiki.gentoo.org/wiki/Portage_with_Git) for configuration details and troubleshooting.

{{< gz-cmd path="/etc/portage/repos.conf/gentoo.conf" slot="gentoo-rsync" set="gentoo_rsync" >}}

{{< /gz-cmd >}}

Then run `emaint sync -r gentoo`.

{{% details title="Distfiles (GENTOO_MIRRORS)" %}}

In `/etc/portage/make.conf`, fill in the distfiles URL from the overview table. You can list several (Portage tries them in order, with the earlier ones taking priority):

{{< gz-mirror name="gentoo-dist" set="gentoo_dist" >}}

{{< gz-cmd path="/etc/portage/make.conf" slot="gentoo-dist" set="gentoo_dist" >}}
GENTOO_MIRRORS="@@LIST@@"
{{< /gz-cmd >}}

After configuration, run `emaint sync -r gentoo` to update the Gentoo ebuild repository.

{{% /details %}}

{{% details title="Official binary packages (binhost)" %}}

The [official Gentoo binary package host](https://wiki.gentoo.org/wiki/Project:Binhost) provides prebuilt, signed packages. Recent Stage 3 archives already configure this repository under `/etc/portage/binrepos.conf/`. To use a mirror, edit `sync-uri` in the `[gentoo]` section.

This configuration uses the current `23.0` profile. See the [amd64 binary package directory](https://distfiles-cdn-origin.gentoo.org/releases/amd64/binpackages/) and [arm64 binary package directory](https://distfiles-cdn-origin.gentoo.org/releases/arm64/binpackages/) for exact paths. The Gentoo Binhost project currently supports amd64 and arm64 with the GNU toolchain (glibc, GCC and binutils); binary packages for other architectures and toolchains are limited to the package cache used by Release Engineering to build Stage 3.

This example uses baseline amd64 x86-64 packages:

{{< gz-mirror name="gentoo-bin" set="gentoo_bin" >}}

{{< gz-cmd path="/etc/portage/binrepos.conf/gentoo.conf" slot="gentoo-bin" set="gentoo_bin" suffix="/releases/amd64/binpackages/23.0/x86-64" >}}
[gentoo]
priority = 1
sync-uri = @@SRC@@
location = /var/cache/binhost/gentoo
verify-signature = true
{{< /gz-cmd >}}

`sync-uri` must point to a directory containing `Packages`. Baseline arm64 systems can change the path to `/releases/arm64/binpackages/23.0/arm64`.

On baseline amd64 systems, use x86-64-v3 packages when the CPU supports [x86-64-v3](https://www.gentoo.org/news/2024/02/04/x86-64-v3.html) for instruction-set-specific optimizations. Check support with:

{{< gz-cmd path="shell" >}}
ld.so --help
{{< /gz-cmd >}}

If the output includes `x86-64-v3 (supported, searched)`, change the final path component above to `x86-64-v3`:

{{< gz-cmd path="/etc/portage/binrepos.conf/gentoo.conf" slot="gentoo-bin" set="gentoo_bin" suffix="/releases/amd64/binpackages/23.0/x86-64-v3" >}}
sync-uri = @@SRC@@
{{< /gz-cmd >}}

To download and install a suitable binary package automatically when one is available, add this to `/etc/portage/make.conf`:

{{< gz-cmd path="/etc/portage/make.conf" >}}
FEATURES="${FEATURES} getbinpkg"
{{< /gz-cmd >}}

When no suitable binary package is available, Portage builds from source as usual.

To use binary packages for one command:

{{< gz-cmd path="shell" sudo="true" >}}
emerge --ask --getbinpkg <package>
{{< /gz-cmd >}}

According to [Portage binpkg changes](https://www.gentoo.org/support/news-items/2026-05-03-portage-binpkg-changes.html), newer Portage verifies remote binary package signatures by default and caches them in the directory set by `location`. Official binhost users no longer need `FEATURES="binpkg-request-signature"`; on the first download, Portage runs `getuto` to create the trusted keyring.

See the [Gentoo Binary Host Quickstart](https://wiki.gentoo.org/wiki/Gentoo_Binary_Host_Quickstart), [Binary package guide](https://wiki.gentoo.org/wiki/Binary_package_guide) and [MirrorZ Gentoo help](https://help.mirrorz.org/gentoo/) for further configuration.

## Gentoo Prefix Bootstrap mirror configuration

Before running the Bootstrap script, choose mirrors with these environment variables:

{{< gz-mirror name="gentoo-dist-prefix" set="gentoo_dist" >}}

{{< gz-cmd path="shell" slot="gentoo-dist-prefix" set="gentoo_dist" >}}
export GENTOO_MIRRORS="@@SRC@@"
export SNAPSHOT_URL="@@SRC@@/snapshots"
{{< /gz-cmd >}}

After Bootstrap completes, replace `/etc` with `$EPREFIX/etc` when changing Gentoo Portage and Distfiles mirrors. `GNU_URL` points at a mirror of the GNU software; take the address from the GNU help page of the mirror you use.
